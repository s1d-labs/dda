DDA website data audit

This report gives the measured scope of the public website of the Delhi Development Authority (dda.gov.in), the checks of the scraped data, and the findings from the data. It uses ASD-STE100 Simplified Technical English. It names no private individuals or firms.

1. Verification of the scrape

We checked the stored records against the site structure. The checks found five defects in the first version of the scraper and three more during the run. We fixed all of them. The table gives each defect and its effect.

The repair pass of 2026-11-05 read all 116 paged listings again. It added 397 pages and 3,988 documents to the scope. The tender archive now has all 285 pages. 76 internal page links return HTTP 404 on the site.

2. Unauthorised colonies (PM-UDAY)

The site publishes the list of 1,731 unauthorised colonies (excluding affluent colonies) and a list of 69 colonies inhabited by the affluent section of society. Both are text PDF files. We extracted all rows without OCR. The table dda.unauthorised_colonies and the file data/unauthorised_colonies.csv hold the result.

The page /delineated-boundary holds a second table with 1,716 rows. Each row gives the boundary map of one colony. We joined the two tables on the registration number.

  • 152 boundary rows have the remark that the boundary can not be delineated as per the SOP. 116 of these give the reason that the shapefile of the colony is not available.
  • All 1,354 final boundary maps have an upload date between 2020-03-11 and 2020-08-14. The table has no update after August 2020.
  • 71 boundary rows have a registration number that is not in the list of 1,731 colonies.
  • The list of 1,731 colonies has 1 registration number that occurs two times.
  • 1,019 of the 1,731 colony entries give a postal district (for example "Delhi-41"). We converted it to a PIN code.

Indicator. About 1 colony in 5 has no final boundary on the site (526 of 1,731). The final boundary is the base for the PM-UDAY ownership process. The public table shows no change since 2020.

3. Tenders, work awards and debarments

The tender pages and the tender archive give 1,919 tender rows with 1,470 different NIT numbers. We read the office code and the financial year from each NIT number (for example 07/EE/HCD-10/DDA/2026-27). The full tender process runs on the central e-procurement portal. The DDA site keeps the notice and the documents.

Coverage note. The first scrape read only 94 of the 285 pages of the tender archive, so it showed almost no tenders for 2022-23 to 2024-25. The repair pass read all 285 pages. The chart now shows these years.

  • 143 tender rows (7.5%) are marked "re-invited". A re-invited tender had no valid bid in the first call.
  • The site has 1,504 work award letters. 288 of them give the NIT number of the tender.
  • The site has 39 debarment or suspension orders and 3 withdrawals of such orders. Most orders are from 2022 to 2025.

4. Historical records

The site keeps old records that are not easy to find with the site navigation. The data makes them searchable.

The villages with the most awards are Bahapur, Kilokri, Mehrauli, Tuglakabad, Tihar.

11,334 of 20,202 listing rows have a date. The count increases strongly after 2019. Older material is mostly in archive sections.

5. Documents

The stored documents use 86.0 GB. The median file is 0.7 MB. Most files are PDF. The table dda.documents gives the status, size and SHA-256 of each file.

  • Duplicate files: 1,252 files occur at more than one URL. The extra copies are 1,494 files (2.4 GB). One file occurs 21 times.
  • Very large files: 60 files are 100 MB or larger. The largest is 0.6 GB. These are mostly scanned orders and agendas.
  • Empty file: 1 PDF file has 0 bytes.
  • Size label: the listing shows a size for 16,641 rows. For 14 rows, the stored file is more than 20% larger or smaller than the label.

6. Site quality and security indicators

These are indicators, not findings of wrongdoing.

  • Legacy TLS. The server needs legacy TLS renegotiation. Modern clients refuse it by default.
  • Incomplete certificate chain. The server does not send its intermediate certificate.
  • Links to raw IP addresses. Some pages link to services by IP address over plain HTTP.
  • Link to a staging server. One page links to a vendor staging host on port 91.
  • Plain HTTP links. 89 external links use http://. Most go to the DDA online services portal.
  • Hindi mirror. The site has 598 Hindi pages and 2,448 English pages. Many English listings have no Hindi page.

7. DDA on the central e-procurement portal

DDA runs its tenders on the central e-procurement portal (eprocure.gov.in). The team database already holds 53,170 DDA tenders from that portal, with tender value, EMD, bid counts and stage. The DDA site keeps the notices and the award letters. Both use the same NIT reference, so we linked them by number, office and financial year (link_eprocure.py).

  • 1,499 of 1,837 tender rows on the DDA site (81.6%) link to an eprocure tender.
  • 244 of 288 award letters with an NIT number link to an eprocure tender.

Indicator. Only 1,070 of 53,170 DDA tenders (2.0%) reach the stage "awarded" on eprocure. 45,894 (86.3%) stay "in evaluation". Of the tenders with an award letter on the DDA site, 240 still show "in evaluation" on eprocure. DDA publishes the award on its own site, not on the portal.

11. Limits

  • Three documents can not be downloaded: the server cuts the transfer or refuses the link.
  • The eprocure data comes from the team database. Its stage reflects the last time the team scraped that tender.
  • The login, OTP and captcha portals of DDA are separate systems. We did not access them.
  • We did not use OCR. Scanned PDF files are stored for later work.
  • Dates come from the listing text. A row without a printed date has no date.
